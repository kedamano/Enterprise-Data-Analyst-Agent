## 四、SDD 评价（规格驱动开发）

**做对的：**
- 规格真被当 contract 用：七份 prompt 逐字落地、14 状态逐字落地、七工具名一一对应、state 字段名与规格 Schema 对齐——不是先写代码后补文档
- 规格本身质量高：职责边界（HOW/WHAT TO DO/GET FACTS/EXPLAIN/IS EVIDENCE ENOUGH/REPORT）、三路决策、反 fabrication 条款均可执行

**裂缝：**
- **缺验收标准**：规格定义「要什么」没定义「怎么算做到」→ Evidence 等六类退化为 dict 而不违反任何条款
- **静默降级无记录**：§21/§22/§23、Redis/PG/Milvus 写进规格却未实现，无 phase 2 标记、无裁剪记录——与项目自己在 LLM 层防的「静默降级」是同一类问题
- **规格未回写**：14 状态中 3 个从未使用，全景图与实现脱节

## 五、TDD 评价

**做对的（含亮点）：**
- conftest 强制 `LLM_NO_FALLBACK=true` + `MOCK_LLM=false` + 后端守卫测试（`test_llm_backend_is_real`），专防 Mock 假绿灯
- 测试是行为契约式：断言业务语义（营收问题识别营收指标、计划工具必须在 REGISTRY、发现必须带证据），对 LLM 非确定性处理成熟（同义词容忍、澄清合法化、防 flaky）
- 五层覆盖结构：后端守卫 → 单阶段 → 七工具实测（真 SQLite）→ 全流水线 → HTTP API

**裂缝：**
- **🔴 `fallback_occurred()` 未定义**：被调用 4 次（test_agent_real.py:45,53,72,88）但 conftest.py 与测试文件均无定义/导入 → 4 个测试必然 NameError，TDD 红绿循环断裂
- **负路径零覆盖**：REPLAN 触发、FAIL 路径、SQL 写入拦截、沙箱逃逸拦截、SSE、/ingest 均无测试——安全护栏没测试等于护栏可能不存在
- **形态为 test-after**：13 个测试对应六节点+七工具+两入口，颗粒度撑不起 test-first 驱动
