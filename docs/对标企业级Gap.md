# Enterprise Data Analyst Agent × 企业级 Agent 对标 Gap 清单

> 定位判断（诚实版）：
> - 作为**面试作品 / 数据 Agent 原型**：优秀，工程护栏密度远超大多数候选人。
> - 作为**企业级生产 Agent**：约 **中游偏上、未达标**。编排 / 安全沙箱 / 评测 / 观测的“工程骨架”已经像样，但缺企业级真正卡脖子的**数据治理、合规、自主性、多租户运维、真数据真业务验证**。
> - 缺的不是前端（有 `/ui` demo，产品级可接 Dify 等低代码替代）。

---

## 一、自主能力（Agent 本体）——最本质缺口

| 现状（已实现） | 企业级要求 | 差距 |
|---|---|---|
| Executor 确定性参数合成 + 固定 7 工具模板（`nodes.build_executor_params`） | LLM **自由写 SQL/Python**、按需调用，沙箱执行 | **最大短板**：参考 DeepAnalyze 的“写码-执行”只移植了沙箱，没移植自由写码。模板表达不了的问题（生存分析 / 显著性检验 / 自建小模型 / 多表任意 join）做不了 |
| 六节点串行流水线（`graph._drive_sync`） | 动态并行子任务、按需扩展 | 全串行、无 DAG / 并行调度（可视化与 SQL 等本可并行） |
| JSON schema 阶段输出 | 原生 tool_calls + **并行工具调用** | 无 parallel tool calling；无 tool_choice 强制某阶段 |
| 单 Agent 多角色阶段 | 需要时多 Agent / 子 Agent 委托 | 无（如“报告评审 Agent”做第二意见 / 对抗检查） |

---

## 二、数据 / 领域层

| 现状 | 差距 |
|---|---|
| 样例 SQLite + 预置表；schema_search 只读元数据 | 无真实企业库 / 多方言真实场景；无数据血缘（row→结论可追溯）；无列级权限 / 脱敏分级；无查询成本 / 行数配额按租户 |
| 知识 = 文档 chunk；PDF 仅 pypdf 抽文本 | 无表格 / 版面理解、无 OCR、无父子 chunk、无索引版本 / 双写一致性、无坏 chunk 回流 |
| 中文、通用术语 | 无行业词表、无 query 改写（改写会引入噪声，需兜底：多路+RRF+引用校验） |

---

## 三、记忆 / 上下文工程

| 现状 | 差距 |
|---|---|
| 短期滚动摘要 + 教训回流（`memory/summarize.py`、`_persist_memory`）+ checkpoint（`checkpoint.py`） | 无**跨副本一致性**（Redis 短记实现有，但默认内存 / 单副本）；无 TTL / 遗忘策略；无“用户偏好 / 报告偏好”结构化长期槽位 |
| token 预算辅助（`memory/budget.py`） | **prompt 组装未真正按预算强制执行**（仅 memory 字段做了 truncate；system / 工具 / 历史整体预算未分配）；无**单会话 token 熔断** |

---

## 四、RAG / 检索

| 现状 | 差距 |
|---|---|
| BM25(+CJK 二元组) + 向量 RRF + 短语亲和重排（`knowledge_tool`/`reranker`） | 无 query 改写、多跳 / 子问题拆分、检索-生成 **fail 兜底**（低置信→换 SQL / 拒答 / 追问）；无检索质量在线分维 |
| rerank 确定性实现，cross-encoder 为钩子 | cross-encoder 未真正上线（本机加载脆弱）；需离线预缓存模型 |
| Milvus 可选后端 | 无索引一致性、embedding 版本迁移、向量与源文档权限对齐 |

---

## 五、安全 / 合规 / 治理（企业级红线区）

| 现状 | 差距 |
|---|---|
| SQL 只读 + 白名单 + 单语句 + 行数 / 语句级超时（`sql_tool`）；AST + 子进程 / Docker 沙箱（`python_tool`）；审计 JSONL（脱敏参数 + 高危标记，`tools/__init__`）；Prompt 注入分层（§21） | 缺 **RBAC / 细粒度权限**（按人 / 角色 / 列）；缺 **两步授权 / 高危确认 HITL** 策略引擎；审计为文件非不可篡改库、无 SQL 审计查询；无 **间接注入对抗测试集**（知识库注入）；无输出 PII 脱敏 / 合规标签 |
| 多租户列（懒迁移，空=全局，`config.default_tenant`） | 默认单租户、浅实现；缺租户配额 / 隔离的接口强制与测试矩阵 |

---

## 六、可靠性 / 可运维

| 现状 | 差距 |
|---|---|
| 三态熔断 + 多模型加权路由 + 降级 + 重试策略（4xx 快速失败，`router`/`circuit_breaker`/`model_router`）；checkpoint 断点续跑 | 无 **k8s / 优雅伸缩 / 差异化探针**；无背压 / 排队（长任务）；长分析只有同步 / SSE，无**异步任务 + 回调** |
| 结构化 span JSONL + `/debug/traces` | 无 **OTel / 指标 / 告警 / SLI-SLO**；日志无采样；无分布式 trace（多服务）；无 P95 监控 |
| Dockerfile + `run-container.sh` | **镜像 11.3GB 未瘦身**（torch 等重依赖全打入）；无 CI/CD / 镜像仓库 / schema 版本迁移 |

---

## 七、评测 / 质量 / 成本治理

| 现状 | 差距 |
|---|---|
| eval 骨架：golden 5 条 + mock/real + 工具轨迹断言 + 禁止项 + 真 token（`app/eval`）；防假绿（conftest） | golden 少、纯自建；**无业务标注集 / 人工评审闭环 / badcase 回流**；无 retrieval-vs-忠实度分维实测；无离线-在线一致性与 A/B / 灰度指标；无幻觉率监控 |
| 成本实算需配单价（`cost_*_per_mtok`） | 无**按租户 / 场景预算封顶与告警**；无语义缓存 / 结果缓存降成本 |

---

## 八、产品 / 交互 / 生态

| 现状 | 差距 |
|---|---|
| `/ui` 对话控制台（气泡 + 执行轨迹 + markdown 报告） | 非产品级：无引用溯源 UI、无图内嵌、无导出（可接低代码 / Dify） |
| 工具为进程内函数 | 无 **MCP**：工具越多越需要统一协议接入（可发现 / 可授权 / 可观测） |
| 多模态 | 不支持（输入纯文本；能产出 PNG 但模型不读图、报告不内嵌图）——需 vision 网关分叉 + 图表自检 |

## 优先级（“企业级”必做排序）

**P0 · 决定它是不是真 Agent（约 1–2 周，面试分水岭）**
1. 给 `python_analysis` 一条「LLM 按需生成分析脚本」的真路径（allowlist + AST 守卫已就绪，缺的是 executor 允许模型写码的分支）。

**P0 · 决定它能不能进生产（约 1–2 周）**
2. 真实评测集 + 检索 / 忠实度分维 + badcase 回流；接一次真实业务库验证。
3. 安全合规最硬三件：鉴权 / RBAC、两步授权 HITL、审计落库（非 JSONL）。
4. 镜像瘦身 + CI + HTTPS / 反代层鉴权。

**P1 · 加分 / 撑故事**
5. 上下文 token 预算强制 + 单会话 token 熔断；语义缓存降成本。
6. 长任务异步化；OTel + 告警；多租户配额与隔离测试矩阵。
7. MCP 接入层；多模态图表自检（vision）。

## 一句话结论

本项目把「**安全执行、可观测、可评测、工程护栏**」做得很像企业级（这是它最值钱的部分）；但离“企业级生产 Agent”还差 **自由写码的自主性、真实数据与评测闭环、安全合规落地、可运维部署体系** 四块——全是 P0，且全与前端无关。
