# 企业级数据分析师 Agent · 企业化开发计划（SDD × TDD · 逐日推进）

> 版本 v1 · 2026-09-09 · 单人全职口径（团队可等比压缩天数）
> 目标：把当前「工程护栏齐全但能力偏模板」的 Agent，推进到「分析师愿意天天用」的企业级水平。
> 依据：`docs/审计报告.md`（现状）、`docs/对标企业级Gap.md`（工程缺口）、`docs/分析师视角缺陷.md`（待建）、DeepAnalyze 借鉴（自由写码）。

## 0. 总纲

### 0.1 愿景与范围
- **愿景**：分析师用自然语言完成**可信、可溯源、可复用**的数据分析；Agent 能**自由写 SQL/Python 执行**，但**每个数字都能点回底层查询**。
- **本期范围（8 周单人）**：Phase A（能力主线）+ Phase B（信任/工程主线）。
- **非目标（明确不做，避免范围蔓延）**：自训模型、多 Agent 平台、GraphRAG、指标语义层重系统（标为 C 里程碑）、BI/调度平台。

### 0.2 铁律（每条对应真实踩过的坑）
1. **规格先行**：任何改动先写 `docs/specs/<N>-<name>.md` 的契约段（输入/输出/失败/边界/权限/可观测），再写代码。
2. **先红后绿**：先写会失败的测试（含负路径），Mock 过 → 再谈真模型。
3. **防假绿**：conftest 强制 `MOCK_LLM=false + LLM_NO_FALLBACK=true`；真实模型套件单独存在；任何静默降级判失败。
4. **数字可溯源**：新增的每个"结论级数字"必须可追到 SQL/step_id（Epic E1）。
5. **改动不破坏基线**：每次收工跑一次回归集 + `python -m app.eval.runner --mode mock`，记入 `docs/progress/DailyLog.md`。
6. **真实模型待验清单**：凡依赖真模型质量的项（写码正确率、统计判断），无 key 前标 `[待真实验证]`，不得声称已达标。

### 0.3 每日循环（Ritual，每天照做）
```
① 读卡：取 docs/开发计划 当日任务卡 + docs/progress/DailyLog 昨日断点
② SDD：更新/新增 docs/specs/<当日>.md（契约：输入/输出/失败/边界/权限/可观测）→ 必要时补 schema/prompt
③ TDD 红：写 tests/<对应>.py 失败用例（正路径+负路径），跑红（不绿不算写完）
④ 实现 → 绿（Mock 全过）
⑤ 回归门禁：pytest 关键套件 + eval mock；真模型项记 [待真实验证]
⑥ 收工：更新 DailyLog（新增用例数/通过数/回退/下一日待办）
```

## 2. 各 Epic 规格要点（SDD 侧）与 TDD 侧交付

### E1 数字溯源（D3–D7）
- **SDD 契约**：`AnalysisResult.findings[].evidence[]` 增加 `sql_id/sql_text_hash`；`ToolResult` 已带 `step_id`；报告渲染时 claim ↔ 查询一一映射；新增 `/api/v1/chat/analyze/trace/{session}`（或复用 `/debug/traces`）返回"claim → 所用查询 → 行样本"。
- **TDD**：
  - `test_evidence_carries_sql_id`：每个含数值的 finding 的 evidence 能链到一条 sql_query step。
  - `test_report_claims_resolve_to_query`：报告里每个数字都能解析出底层查询（mock 确定性）。
  - 负路径：finding 无数值则不要求溯源；无证据断言 fail（复用 eval `must_not`/规则）。
- **关联**：`state.py`/`analyst` prompt、`report_tool`、`nodes._to` step 事件。

### E2 自由写码（D8–D13）—— 分析师痛点 ② + Gap P0-1
- **SDD**：Analyst 阶段允许模型产出自定义分析步骤，两种形态：`sql_text`（SQL lint + 只读守卫，复用 `sql_tool` 白名单）或 `python_code`（AST allowlist + 沙箱，复用 `python_tool`）；新增"人审可选"`confirm` 字段；产物与溯源自动挂 step_id。
- **TDD**：
  - 自由 SQL：合法 join/聚合执行并返回（mock 断言非空、行数受限）；**注入/DML 拒绝**（复用负路径）。
  - 自由 Python：生成分析脚本沙箱执行、产物回传；危险模块/逃逸拒绝。
  - 失败回注：执行失败 → 结构化错误 → 下一轮自纠错（已有 REPLAN 反馈通道）。
- **真模型质量**：`[待真实验证]`（key 到位后跑 golden 新增"自定义分析"类用例）。

### E3 中间结果迭代（D14–D17）—— 分析师痛点 ①
- **SDD**：会话内存引入"最近数据集表"（`session_last_dataset`：schema+rows+来源 sql_id），多轮时若新 query 是"对上一结果操作"（下钻/改期/换粒度），跳过前几步直接作用于该表；提供显式"重跑全链"开关。
- **TDD**：`test_iteration_skips_replan_for_prior_dataset`（同 session 第二次只触发目标阶段）；`test_force_full_rerun`；口径切换仍正确（mock）。

### E4 质量/口径 + 脱敏（D19–D23）
- **SDD**：`dataset_profile` 输出加 主键唯一性/join 放大/粒度/日期连续性 检测；输出脱敏分级配置（默认 mask 敏感列，不进 LLM 上下文/仅取样本）；Reflection 增加"口径可比性"检查项。
- **TDD**：profile 新指标正确性；脱敏后 prompt 不含原始行/列值；口径漂移样例被 Reflection 拒。

### E5 统计严谨 + 导出（D24–D26）
- **SDD**：Python 模板允许使用 scipy；报告要求显著性/样本/季节声明（prompt 规则 + schema 字段 `stats_notes`）；`/export`（或 UI 按钮）导出 SQL/CSV。
- **TDD**：显著性代码路径 mock 断言有输出；无样本量结论被拒/标注。

### E6 真实评测 + 成本轻路径（D27–D30）
- **SDD**：eval 增加"自由写码/溯源/迭代" golden 子集；真实模式跑通；新增**轻路径**：可直接由 SQL 回答的小问不走全链（跳 Reflect/Reporter 简版）。
- **TDD**：eval mock 全绿 + `--mode real` 冒烟；轻路径命中判定单测。

### E7 多源 + 部署硬化（D31–D34）
- **SDD**：多 `data_db_url` 命名源；镜像瘦身 `Dockerfile.prod`（目标 <2GB）；安全说明（鉴权/HTTPS）。
- **TDD**：多源参数化用例；`docker build` + 容器冒烟 CI 化。

## 3. 全局质量门禁（每次收工必跑）
```bash
python -m pytest tests/ -q --ignore=tests/test_agent_real.py   # 离线全量
python -m app.eval.runner --mode mock                          # 质量/成本基线
# 关键 Epic 完成后另跑对应 *_live / docker_live；有 key 时：
python -m pytest tests/test_agent_real.py -v
python -m app.eval.runner --mode real
```
**DoD（Epic 级）**：规格文档 ✅ → 红绿测试 ✅（正+负）→ 回归与 eval 无回退 ✅ → DailyLog 记录 ✅ → 真模型项已标 `[待真实验证]` 或已验 ✅。

## 5. 风险与对策
- 真实 key 未到位 → E2/E5 质量不可验：**先建 mock 契约与待验清单**，到位即转真实（对策：把 B-3 前置）。
- 自由写码打开攻击面 → 只读/白名单/AST/沙箱全保留；写码仅在"明确允许的分析步骤"内，默认关闭 flag。
- 迭代语义误判（模型把新问题当旧结果操作）→ 只对显式指代词（"基于上一结果/改为/只看"）触发，否则全链。
