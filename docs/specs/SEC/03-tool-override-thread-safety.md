# SEC/03 工具覆盖栈线程安全 — 规格 v1.0（D70 定稿）

> 动因：`graph.py:43` 的 `_TOOL_OVERRIDE_STACK` 是全局可变列表，并发请求会互相污染。
> 现状：测试/Replay 用工具覆盖在并发场景下可能注入到错误的请求。
> 核心判断：改用 `contextvars.ContextVar` 实现请求级隔离。

## 1. 契约（Contract）

### 参数契约

| 参数 | 必需 | 说明 |
|---|---|---|
| `overrides` | 是 | 工具覆盖字典 `{tool_name: replacement_fn}` |

### 输出契约

```json
{
  "applied": "bool",
  "token": "contextvars.Token"
}
```

### 判定规则

1. `_TOOL_OVERRIDE_STACK` 改为 `ContextVar[list]`
2. 每个请求有独立的覆盖栈
3. 嵌套覆盖仍然支持（LIFO 恢复）
4. 请求结束时自动清理

### 边界与失败

| 情形 | 行为 |
|---|---|
| 并发请求 A 和 B 同时覆盖 | 各自独立，互不干扰 |
| 嵌套覆盖 | 内层退出只恢复内层 |
| 请求结束 | 自动清理覆盖栈 |

### 可观测

- 无

## 2. TDD（红→绿）

| 用例 | 断言 |
|---|---|
| 正路径：单请求覆盖 | 覆盖生效 |
| 负路径：并发请求隔离 | 请求 A 的覆盖不影响请求 B |
| 兼容性：嵌套覆盖 | LIFO 恢复正确 |
| 兼容性：既有测试 | 全部通过 |

## 3. 验收（Acceptance）

| 项 | 判据 |
|---|---|
| 功能点 | 并发请求工具覆盖隔离 |
| 兼容性 | 既有测试全部通过 |
| 性能 | 无显著退化 |

## 4. 明确不做（Out of Scope）

- 不改变工具覆盖的 API 签名
- 不改变 REGISTRY 的行为
- 不添加线程锁（ContextVar 天然隔离）
