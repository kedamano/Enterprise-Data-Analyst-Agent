# RAG-01 · 低置信检索的 fail-closed 兜底

> 2026-09-15（D53）· 对应 `docs/对标企业级Gap.md` §四 残留项 3
> 「检索-生成 **fail 兜底**」这一条**从未开工**——`retrieve` / `knowledge_search`
> 无论检索到什么都照单返回，调用方无从分辨"真查到了"与"只查到了几个字面相近的段落"。
>
> 上游背景：`rerank_score` 早已在 `rag/reranker.py` 算出来（`0.8*短语亲和 + 0.2*归一融合分`），
> **但没有任何人读它**——"实现了但从未接线"，与 D42 的 `fit_to_budget` 同一种病。

---

## 1. 断在哪（现状复核）

| # | 现状 | 后果 |
|---|---|---|
| 1 | `knowledge_tool.run()` 返回 `{"ok": True, "chunks": [...]}`，**没有任何置信信息** | 检索到 0 个相关段落与检索到 4 个无关段落，**在调用方看来一模一样** |
| 2 | `rerank_score` 算了但不外传 | 唯一的置信信号被丢掉 |
| 3 | 低置信时照样把 chunks 交给模型 | 模型把无关段落当**知识**写进结论 → **幻觉的一个来源**，且现有 E1 溯源管不到（溯源管的是"数值 claim 有无 SQL"，不管"知识 claim 有无依据"） |
| 4 | 检索出错时 `run()` 返回 `ok=False` | 这一条**已经**是对的（fail-closed），本次不改 |

**核心判断**：本卡不做"提高召回"（那是 query 改写/多跳的事），只做
**"让调用方知道这次检索值不值得信，并且让低置信的知识进不了报告"**。

---

## 2. 契约

### 2.1 置信度口径（唯一来源）

新增 `app/core/rag/confidence.py`：

```python
@dataclass(frozen=True)
class Confidence:
    level: str      # "high" | "low" | "none"
    score: float    # 0.0 ~ 1.0；none 时为 0.0
    basis: str      # 这个分是**怎么来的**：见下表

def confidence_of(query: str, chunks: list[dict]) -> Confidence: ...
```

| `basis` | 何时使用 | 含义 |
|---|---|---|
| `phrase_affinity` | 首条有文本（**正常路径，与重排开关无关**） | 现算 `_phrase_affinity(query, 首条.text)`，复用 `reranker` 的同一函数（**口径不写两遍**） |
| `no_chunks` | chunks 为空 | `level="none"` |
| `no_signal` | 有 chunks 但首条没有可判文本 | **按 `low` 处理（fail-closed）**，绝不因"算不出来"而默认高置信 |

> **`rerank_score` 不参与判级**——这是对初版设计的**推翻**，依据是下面的实测，不是偏好。

分级（阈值 `settings.rag_min_confidence`，默认 **`0.15`**）：

- `none`：无候选；
- `low`：`0 <= score < 阈值`；
- `high`：`score >= 阈值`。

#### 2.1.1 阈值是量出来的，不是拍的（2026-09-15 实测）

黄金集 6 正例 + 1 负例，两种模式各跑一遍（纯 BM25，`RERANK_ENABLED` 拨动）：

| 模式 | 正例首条得分（6 条） | 负例首条得分 |
|---|---|---|
| 重排**关**（本机 `.env` 实况），取 `_phrase_affinity` | `0.188 / 0.250 / 0.273 / 0.273 / 0.444 / 0.500` | **`0.000`**（或 0 段） |
| 重排**开**，取 `rerank_score` | `0.200 / 0.218 / 0.350 / 0.418 / 0.556 / 0.600` | **`0.200`** |

两条结论直接决定设计：

1. **单一阈值不可能同时伺候两个尺度**。重排关上时阈值必须 `≤ 0.188`；重排打开时负例恰好落在 `0.200`
   （`0.8×亲和0.0 + 0.2×归一1.0`——**RRF 归一化项的地板分**），阈值必须 `> 0.200`。
   交集为空。初版的 `0.2` 默认值在重排打开时会把**完全无关**的首条判成 `high`。
2. **判级改用亲和分这一个尺度**（`basis="phrase_affinity"` 与重排开关无关）。
   否则"拨一下重排开关，同一次检索从 high 变 low"——**同一件事两个定义**，
   正是 D41（"已溯源"有两个定义）、D47（表名解析要复用 gate）踩过的坑。
   `rerank_score` 仍在 chunk 里透出，**不丢信号，只是不当判据**。
3. 阈值取 **`0.15`**：正例最小 `0.188`（余量 `0.038`），负例 `0.000`（余量 `0.15`）。
   余量不大是这套打分的固有性质（`|q∩t| / |q|` 会让长问句被稀释），
   故 §3 用**两侧标定**钉住，而不是靠"看起来合理"。

**为什么取首条**：RAG 的失败模式是"首条就不相关"，后面几条更不相关；
对全体取平均会让一条高分的正确段落把一个无关段落抬过阈值。

**已知误判（如实记录，不在本卡解）**：字面大量重合但语义不相干的问句
（如"华东区域的年会在哪里办"，亲和 `0.273` → 判 `high`）现口径分不出来，
需要嵌入相似度或 cross-encoder 才能压下去，见 §4。


### 2.2 工具输出（fail-closed：低置信**不下发内容**）

`knowledge_tool.run()` 的返回增加字段（其余字段一字不动）：

```python
{"ok": True,
 "chunks": [],                    # 低置信时**为空**——理由见下
 "confidence": {"level": ..., "score": ..., "basis": ...},
 "low_confidence": True/False,    # level != "high" 时为 True
 "note": "..."}                   # 低置信时给出可读说明（含"命中了 N 段但相关性不足"）
```

**为什么低置信要清空 `chunks`（而不是只标记）**——这是本卡最要紧的一个决定：

复核发现，**今天根本不存在"知识引用通路"**：`sources.append_citations`
（`app/core/agents/data_analyst/sources.py:158`）只处理**数值 evidence**，
知识 chunk 从来不进任何引用块。所以"在引用环节过滤低置信知识"**没有可挂的钩子**——
写了也只是一句无处的注释。

于是只剩两条路：

| 方案 | 后果 |
|---|---|
| 保留 chunks 并标记 | 模型**照样能读到**这些段落，靠 prompt 说"别引用"——**提示词纪律冒充保证**，本项目的既有教训（见 D42/D47） |
| **低置信时清空 chunks** | 模型**读不到**就不可能引用它——**结构性保证**，与脱敏的 `fail-closed`（"出错必须丢掉行样本，而不是放行原始数据"）同一条纪律 |

选后者。代价是"字面不重合但语义正确"的查询会变空——**这个代价由 §3 的两侧标定来兜**：
黄金集 6 条正例必须仍为 `high`（不误伤），唯一的负例必须不为 `high`。
命中的段数写进 `note`，人工排查时仍知道"差点匹配到什么"，但**内容不进模型上下文**。

### 2.3 报告侧：知识缺失必须**明说**

低置信时模型拿不到内容，因此**不得**据此断言。为了不让它"假装查过"，
工具返回的 `note`（含 `low_confidence=true`）会被**原样送进 analyst 的上下文**——
`nodes.run_analyst` 把整个 `tool_result.output` 序列化进 payload
（`app/core/agents/data_analyst/nodes.py:1056`），无需额外接线。

**边界要说清**（不比实际做到的写得更多）：

- **保证的**：① 知识内容**不进模型上下文**（`chunks == []`，结构性）；
  ② "知识库没查到"这件事**到得了模型眼前**（`note` 在 payload 里，有用例钉住接线）。
- **不保证的**：模型仍可能在**没有依据**的情况下编出知识性断言。
  那属于**幻觉**，由 E6 的 `hallucination_rate` / 溯源检查覆盖，**不在本卡**——
  本卡只负责把"可依据的东西"清零，不负责模型的自律。

### 2.4 失败与边界

| 情形 | 行为 |
|---|---|
| 空 query | 既有行为不变（`ok=False`，`缺少 query 参数`） |
| 检索抛异常 | 既有行为不变（`ok=False` + `chunks=[]`），**不得**返回 `low_confidence=False` |
| 空知识库 | `level="none"`，`low_confidence=True` |
| 重排开关 | 与判级**无关**（都走 `phrase_affinity`）；`rerank_score` 若存在则原样透出 |
| 阈值配置非法（负数/非数） | 退回默认 `0.15`，不抛 |

### 2.5 可观测

- 新增计数器 `rag_low_confidence_total`（进 `/metrics`），
  与 D44 的 SLI 纪律一致：**只有计数，不记录查询内容**（知识库查询可能含敏感词）。

## 3. 验收

| 项 | 判据 |
|---|---|
| 口径唯一 | `phrase_affinity` 路径**复用** `reranker._phrase_affinity`（源码级断言，不写第二份实现） |
| 判级与重排无关 | `RERANK_ENABLED` 开/关时，同一批黄金集样本的 `level` **逐个相同**（防"拨开关换结论"） |
| 高置信 | 查询与段落高度重合 → `high` 且 `low_confidence=False` |
| 低置信 | 查询与库内内容无关 → `low` 且 `note` 明写不得据此断言 |
| 空库 | `none` / `low_confidence=True` |
| **fail-closed** | 算不出信号 → `low`（**不是** `high`）；检索异常 → 仍 `ok=False` |
| **两侧标定** | 黄金集 6 条正例首条得分**全部 `>= 阈值`**（不误伤）；唯一负例**不 `high`**（不放水） |
| **低置信不下发** | 低置信时 `chunks == []`，且 `note` 说明命中了 N 段但不足——**内容进不了模型上下文**（结构性保证，非 prompt 纪律） |
| 报告明说 | `note` 与 `low_confidence` **确实进到 analyst 的 payload**（钉住 `run_analyst` 的接线）；内容不在上下文里。模型凭空编造归 E6 幻觉率管，不在本卡 |
| 阈值可配 | `RAG_MIN_CONFIDENCE` 生效；非法值退回默认 |
| 不回归 | 既有 `test_hybrid*` / `test_rerank*` / `test_knowledge*` / `rag_eval` 全绿 |

## 4. 明确不做（留给下一张卡）

- **query 改写**（同义/缩写/口语 → 检索用语）
- **多跳拆分**（复合问题拆成子问题分别检索再合并）
- cross-encoder 上线（仍是钩子）
- **字面重合同的语义误判**（"华东区域的年会在哪里办" → 亲和 0.273 → 判 `high`）：
  亲和分只看字面，压不住这类问句。要压得下去，需要把向量余弦或 cross-encoder 分数
  也纳入判据——那会同时改动检索排序，与本卡"只加判据、不动排序"的边界冲突。
  本卡把它**如实写进已知误判**，不假装已解决。

前三项都是**提召回**，与本卡的**提可信**是两个方向；混在一张卡里会让"召回变好还是阈值放水"
分不清。本卡的阈值为它们留好参数位。
