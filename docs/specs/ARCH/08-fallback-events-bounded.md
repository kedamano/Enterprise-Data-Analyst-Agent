# ARCH/08 降级事件无界增长修复 — 规格 v1.0（D70 定稿）

> 动因：`router.py:265` 的 `_fallback_events` 是无界列表，长时间运行会内存泄漏。
> 现状：每次 LLM 降级都 append 事件，从不清理。
> 核心判断：改用有界队列（deque），最多保留最近 100 条事件。

## 1. 契约（Contract）

### 参数契约

| 参数 | 必需 | 说明 |
|---|---|---|
| `stage` | 是 | 降级发生的阶段 |
| `error` | 是 | 错误信息 |

### 输出契约

```json
{
  "recorded": "bool",
  "total_events": "int"
}
```

### 判定规则

1. `_fallback_events` 改为 `collections.deque(maxlen=100)`
2. 新事件加入时，最旧事件自动淘汰
3. 线程安全（使用锁保护）

### 边界与失败

| 情形 | 行为 |
|---|---|
| 队列满 | 自动淘汰最旧事件 |
| 多线程并发 | 锁保护 |

### 可观测

- 无

## 2. TDD（红→绿）

| 用例 | 断言 |
|---|---|
| 正路径：记录事件 | 事件被记录 |
| 负路径：超过 100 条 | 只保留最近 100 条 |
| 兼容性：既有测试 | 全部通过 |

## 3. 验收（Acceptance）

| 项 | 判据 |
|---|---|
| 功能点 | 事件队列有界 |
| 兼容性 | 既有测试全部通过 |
| 内存 | 不会无界增长 |

## 4. 明确不做（Out of Scope）

- 不改变 `record_fallback` 的 API
- 不改变 `fallback_events` 的返回格式
- 不引入外部存储
