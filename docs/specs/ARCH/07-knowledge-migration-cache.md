# ARCH/07 KnowledgeStore 迁移缓存 — 规格 v1.0（D70 定稿）

> 动因：`knowledge_tool.py:279` 的 `KnowledgeStore.__init__` 在每次实例化时都运行 8+ ALTER TABLE 迁移。
> 现状：每次创建 KnowledgeStore 都检查并执行迁移，即使表结构已是最新。
> 核心判断：迁移结果按 DB 路径缓存，相同 DB 路径不重复执行迁移。

## 1. 契约（Contract）

### 参数契约

| 参数 | 必需 | 说明 |
|---|---|---|
| `db_path` | 是 | 知识库 SQLite 文件路径 |

### 输出契约

```json
{
  "migrations_applied": "list[str]",
  "cache_hit": "bool"
}
```

### 判定规则

1. 迁移状态按 DB 路径缓存
2. 相同 DB 路径的 KnowledgeStore 实例共享迁移状态
3. 迁移只执行一次（首次创建时）
4. 线程安全（使用锁保护缓存）

### 边界与失败

| 情形 | 行为 |
|---|---|
| 缓存命中 | 跳过迁移，直接返回 |
| 缓存未命中 | 执行迁移，缓存结果 |
| 迁移失败 | 抛异常，不缓存 |

### 可观测

- 无

## 2. TDD（红→绿）

| 用例 | 断言 |
|---|---|
| 正路径：相同 DB 路径第二次实例化 | 不执行迁移 |
| 负路径：不同 DB 路径 | 执行迁移 |
| 兼容性：既有测试 | 全部通过 |

## 3. 验收（Acceptance）

| 项 | 判据 |
|---|---|
| 功能点 | 迁移按 DB 路径缓存 |
| 性能 | 重复实例化不执行迁移 |
| 兼容性 | 既有测试全部通过 |

## 4. 明确不做（Out of Scope）

- 不改变 KnowledgeStore 的 API
- 不改变迁移逻辑
- 不引入外部缓存
