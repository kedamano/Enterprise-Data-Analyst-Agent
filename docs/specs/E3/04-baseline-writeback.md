# E3/04 增量产物回写为「上一结果」基线 — 规格 v1.0（D17）

> 01 定义了「上一结果」= 最近一次成功数据步；但没定义**增量轮之后**谁是「上一结果」。
> 04 定夺：**增量产物（新 CSV）成为下一轮基线**，从而支持连续下钻（改口径→下钻→再筛）。

## 1. 语义
- 「上一结果」= 会话数据集 `last_dataset`，随每轮**最新的可用表格结果**前移。
- 数据步来源有两类：① `sql_query`/`freeform` 的物化 CSV（01）；② **增量轮的 python 产物 CSV（04）**。
- 回写后 `last_dataset` 带 `derived_from = 上一轮 step_id`，形成可追溯的推导链；
  守卫（02/03）即按**新列**重新判定——这正是「基线前移」与守卫必须配套的原因。

## 2. 判定：只认「本步产出/覆盖的 CSV」
- **不能用** `ToolResult.artifacts` 判据：`python_analysis` 的 artifacts 是
  `session_workdir` 下所有 `.csv/.png/.json`，**包含输入 CSV 与历史产物**，取用会回写错文件。
- **也不能只比「文件集合」**：模型常沿用固定文件名（`out.csv`）**原地覆盖**，只比新出现的
  文件名会全部漏判；而且 session workdir 跨轮次/跨进程留存，上一轮遗留的同名文件会让 diff 恒为空。
- 正解：记录本步**起始时刻**，取 `mtime ≥ 起始时刻`（留 1s 时钟粒度余量）的 `.csv` → 本次产出/覆盖者。
  旧遗留文件 mtime 早于本步，天然排除；多命中取 mtime 最新者。
- 无此类 CSV（如只出 PNG、仅 stdout）→ **基线不变**（保守，绝不前移到不可用的东西上）。

## 3. 边界
- 回写仅在增量步 **SUCCESS** 时发生；失败轮基线不变（该轮本就未产出可信结果）。
- 新 CSV 必须能解析出列（`_csv_columns` 非空）才回写，否则视为不可用。
- 日期列与范围按 02 的 `_date_bounds` 重新探测（新基线可能有不同时间列）。
- 回写仅影响**本会话**（short_term），跨会话隔离不变。
- 全链轮仍由 `sql_query`/`freeform` 的结果覆盖基线（既有行为），增量产物不与之竞争。
