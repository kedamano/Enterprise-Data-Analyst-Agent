# E3/03 口径切换与维度可用性守卫 — 规格 v1.0（D16）

> 承接 01（增量触发）/02（目标阶段）。02 保证「命中了就只做那一步」，
> 03 保证「**不该命中的绝不命中**」——增量只能在**上一结果真的支持**该操作时发生。
> 依据：开发计划风险条「迭代语义误判（模型把新问题当旧结果操作）」。

## 1. 负路径契约（不满足 → 回退全链，`metadata["iteration_skip"]` 记原因）

| # | 情形 | 判定 | 结果 |
|---|---|---|---|
| N1 | **未指代**：会话虽有数据集，但本轮是全新问题（无指代词） | `is_followup()` 为假 | 全链（01 已定，D16 补显式用例） |
| N2 | **口径切换**：请求的度量（metric）在上一结果里**不存在** | 度量词 → 列模式匹配失败 | 全链（必须回数仓重取） |
| N3 | **维度不可用**：下钻/筛选/分组用到的维度在上一结果里**不存在** | 维度词 → 列模式匹配失败 | 全链（必须 join 维表重取） |
| N4 | 无数据集 / 改期越界 / 时间粒度无日期列 | 01、02 守卫 | 全链 |

> 依据：上一结果是**某次查询的投影**——它只含那次 SELECT 的列。拿它硬算新口径或新维度，
> 只会得到「列不存在」的失败或（更糟）静默算错。因此 N2/N3 必须在生成脚本**之前**确定性拦截。

## 2. 度量 / 维度词表（可扩展，确定性）
- 度量（N2）：`营收/收入/销售额`、`订单数/订单量`、`客户数`、`销量`、`利润`
  → 列模式如 `revenue|sales|amount` / `orders|order_cnt` / `customers|customer_cnt` / `qty|quantity` / `profit|margin`。
- 维度（N3）：`城市`、`区域/地区`、`产品`、`品类/类别`、`渠道`、`月份`、`日期`
  → 列模式如 `city` / `region` / `product` / `category` / `channel` / `month` / `date`。
- 匹配大小写不敏感、子串匹配（`region` 命中 `region_id` / `region_name`）。
- **只用双字词**（`月份`、`日期` 而非 `月`、`日`），避免 `2024年3月` 被误判为「要月份维度」。

## 3. 边界
- 未提到任何度量/维度的请求（如「只看 region 1 的营收」只提了值）→ 不受 N2/N3 约束。
- 数据集的 `columns` 为空（如 0 行结果）→ 视为「无可解析列」，任何度量/维度均判不可用 → 全链（保守）。
- 守卫只判**列存在性**，不判**值合法性**（「只看华东」而数据里无华东由沙箱如实报错，不属本守卫）。
- 命中 N2/N3 时 `guard["missing"]` 列出缺失词，便于审计与提示用户。

## 4. TDD（正 + 负）
- N1 负：有数据集 + 「各区域营收是多少」→ 不增量、planner 被调用。
- N2 负：数据集只含 `revenue` + 「改成按订单数看」→ 全链，reason 含缺失度量。
- N3 负：数据集只含 `region_id/revenue` + 「下钻到城市」→ 全链，reason 含缺失维度。
- 正：度量/维度在数据集中存在（`orders`、`region_id`）→ 仍走增量且 kind 正确。
- 回归：E3 既有 12 用例与全量套件不回退。
